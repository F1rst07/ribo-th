# RIBO-TH — Robot Control System

โครงงานเว็บไซต์สำหรับเรือหุ่นยนต์อัตโนมัติเก็บขยะและคราบน้ำมันบนผิวน้ำ โดยใช้ Arduino UNO Q กับกล้อง Logitech C270

## สถานะปัจจุบัน (31 ตุลาคม 2569)

- ย้ายโครงสร้างสู่ **Next.js (App Router + TypeScript)** เรียบร้อยแล้ว
- หน้าสาธารณะแสดง **หน้า Under Construction** ตามมาตรฐาน Design System
- ไอคอน Lucide ถูกเก็บเป็น Local SVG ภายในโปรเจกต์พร้อมระบุสิทธิ์ ISC
- **Deploy ขึ้น Vercel เรียบร้อยแล้วที่:** [https://ribo-th.vercel.app](https://ribo-th.vercel.app)
- หน้า Public ยังไม่ได้เชื่อมต่อ Arduino หรือกล้องจริง

หน้า `/dashboard` ใช้สำหรับดูภาพกล้อง สถานะการตรวจจับ และเตรียมการควบคุม UNO Q ระบบรองรับการประมวลผล Local Offline ทั้งโหมดพัฒนาบน Mac และโหมด Edge AI บน UNO Q โดยโหมดใช้งานจริงมีสถาปัตยกรรมดังนี้:

```text
C270 → UNO Q Camera Service → Local ONNX Runtime → Next.js Dashboard
```

บริการบนบอร์ดเริ่มอัตโนมัติด้วย systemd และไม่ต้องต่อ Mac เพื่อประมวลผล AI ส่วน Wi-Fi ใช้สำหรับเปิด Dashboard และส่งคำสั่งผ่านเครือข่ายเท่านั้น ไม่มีการส่งภาพไปยังบริการ AI ภายนอก

ขณะเปิดกล้อง ระบบใช้เฟรมล่าสุดหลังผลรอบก่อนเสร็จ จำกัดงาน inference พร้อมกันหนึ่งคำขอ และรันโมเดลย่อยแบบขนานบน CPU ของบอร์ด ความเร็วจริงขึ้นอยู่กับภาพ อุณหภูมิ และโหลดของอุปกรณ์

## เปิดดูเว็บไซต์

ติดตั้งแพ็กเกจด้วย `npm install` เริ่มต้นเซิร์ฟเวอร์ Local AI ด้วย `npm run ai` และเปิดเซิร์ฟเวอร์เว็บด้วย `npm run dev` จากนั้นเปิด `http://localhost:3000/dashboard` เพื่อทดสอบระบบควบคุมและตรวจจับขยะ สำหรับทดสอบนี้เปิดใช้เฉพาะ localhost ในโหมดพัฒนา

> ไอคอน Lucide ปัจจุบันโหลดจาก CDN จึงต้องเชื่อมอินเทอร์เน็ต หากนำไปใช้จริงระยะยาวควรดาวน์โหลด SVG มาเก็บในโปรเจกต์พร้อมไฟล์ LICENSE ที่เกี่ยวข้อง

## ให้ AI พัฒนาต่ออย่างไร

1. อ่าน `README.md`, `DESIGN_SYSTEM.md` และ `ROADMAP.md` ก่อนแก้โค้ด
2. รักษาหน้า Under Construction เป็นหน้าสาธารณะจนกว่าเจ้าของจะสั่งเปิดจริง
3. เพิ่มระบบเป็นขั้นตอนและทดสอบทีละส่วน ห้ามสร้างระบบควบคุมฮาร์ดแวร์ทั้งหมดรวดเดียว
4. ห้ามสร้างปุ่มสั่งมอเตอร์ที่เชื่อมต่อใช้งานจริงโดยไม่มีการยืนยันตัวตน สิทธิ์ และระบบหยุดฉุกเฉิน
5. หากต้องย้ายไป Next.js ให้รักษาธีม ข้อความ และพฤติกรรมจากหน้า HTML ต้นฉบับ
